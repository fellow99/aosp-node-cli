## 1. 背景与定位

### 1.1 一句话定位

**以 AAR 形式发布的、Android 版 `node` / `npm` / `npx` / `corepack` 命令行**——与
aosp-node-runtime 同一棵官方 Node 源码树交叉编译的 `libnode_cli.so`（arm64-v8a，exec 型 PIE），
在终端里由 node-pty 经 `forkpty` + `execve` 启动；`npm`/`npx`/`corepack` 经**壳脚本作 lib**
（`libnpm.so` / `libnpx.so` / `libcorepack.so`，内容为 sh，见 D6）直出命令；npm/corepack
JS 树作为 assets 随包（纯数据，不需要 exec 位），首启幂等物化到 `filesDir`。

### 1.2 为什么需要它

- 原生 Android 没有现成的 node：`/system/bin` 只有 mksh 与 toybox；
- 进程内引擎（`libnode.so`）每进程只能 `node::Start` 一次，且不是可 `exec` 的文件形态；
  终端（PTY）天然多进程，需要**独立进程的 node CLI**；
- `node::Start` 每进程一次的约束对 CLI 不构成障碍——CLI 是独立进程，与进程内引擎互不冲突。

### 1.3 边界（在范围 / 不在范围）

| 在范围内 | 不在范围内 |
|---|---|
| `libnode_cli.so` 的交叉编译、exec 型 ELF 门禁、AAR 打包、发布 | 任何嵌入 API / Kotlin 桥（属 aosp-node-bridge） |
| npm / corepack JS 树的随包、物化与 sha256 出处记录 | pty 会话管理 / 终端 UI（属消费方或 aosp-node-shell） |
| **npm/npx/corepack 壳脚本打入（D6）+ jniLibs 兄弟文件白名单扩展（§6.1）** | node 引擎共享库（`libnode.so` 由 aosp-node-runtime 提供） |
| 环境变量契约与回程探针定义（§7） | pnpm 本体（pnpm 12+ 为 Rust 可执行件，独立线 `aosp-pnpm-cli`，工作区方案 §9.3） |
| 版本配对事实源 `node-cli.lock.json` | `npm i -g` 安装脚本的 shebang 改写器（M2 可选评估项 ⬜，见 §7 已知限制 1） |

## 2. 版本规则（与 `aosp-node-runtime` 的配对）

1. **版本恒等于 Node 版本**：`io.github.fellow99:node-cli:<node>` ↔ `node-runtime:<node>` ↔
   `node-pty:<node>`，三者在消费方 APK 内必须**同版本上线**（与 pty 同一配对纪律）；
2. 配对是**版本纪律**而非编译期链接：CLI 与引擎是两个不同形态的制品
   （exec 可执行 vs dlopen 共享库），互不 `DT_NEEDED` 挂靠；
3. 当前 draft 计划版本 **26.13.0**：与已发布的 node-runtime / node-pty 26.13.0 配对
   （Maven Central 实测 latest，见工作区 `docs/发布到maven-central.md` 附录 A）；
   M1 首个真实 CI 构建后回写 lock 事实；
4. runtime 升版是本仓的强制重编事件（跟随机制在 M4 建立）；
5. npm **不单独钉版**：随 node 源码树 `deps/npm` 分发（v26.13.0 树内 npm 11.20.0），版本与树
   sha256 记入 lock.builtFrom（§8）——升级 node 即升级 npm；corepack **单独钉版**（v2.2 as-built：
   Node 25 起 corepack 不再随 node 树分发，v26.13.0 树内无 `deps/corepack`——改钉官方 registry
   tarball（当前 0.36.0，engines 覆盖 ≥26），镜像 python-cli pip wheel 纪律）。

## 3. 总体架构与关键决策

```
┌─ 消费方 App 进程 ───────────────────────────────────────────────────────┐
│  环境引导层（bridge 载荷或 Kotlin）                                       │
│   - assets/node-bridge-tools/ 幂等物化 → filesDir（npm/corepack JS 树）  │
│   - 注入 HOME/TMPDIR/PATH/LD_LIBRARY_PATH/NODE_TOOLS_DIR/npm_config_*    │
│   - $HOME/bin symlink 农场：node→libnode_cli.so，npm/npx/corepack→壳脚本  │
│        │ pty.spawn(<nativeLibraryDir>/libnode_cli.so 或壳脚本, args, env)│
│        ▼                                                                 │
│  node 子进程（exec 型，独立生命周期；forkpty → setsid → TIOCSCTTY）        │
│  （node::Start 每进程一次不影响本仓：CLI 独立进程，与进程内引擎互不冲突）    │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.1 关键决策记录（不可回归项）

| # | 决策 | 理由 | 反面（禁止） |
|---|---|---|---|
| **D1** | **exec 打包 `useLegacyPackaging=true`**（物理落盘 nativeLibraryDir） | C1：targetSdk≥29 SELinux 禁止从可写数据目录 exec；库不落盘则 `execve` ENOENT | `useLegacyPackaging=false`（pty dlopen 库的口径，与本仓相反） |
| **D2** | **与 runtime 同一棵官方源码树、android_configure 不带 `--shared`** | 默认 make 目标即产出 `node` 可执行 PIE；同源同 CI 口径可复现 | 为 CLI 加 `--shared`（产出的是库不是可执行）；fork 上游源码 |
| **D3** | **产物唯一 ELF 且改名 `libnode_cli.so`；`libc++_shared.so` 不随包** | Android 打包只认 `lib*.so`；引擎 soname `libnode.so` 被 runtime 占用，同目录不可重名；C++ 运行时由 runtime 统一供给防包内同名冲突（provision BANNED_IN_AAR 已实现双禁） | 命名 `libnode.so`；随包携带 `libc++_shared.so` |
| **D4** | **CLI_VERSION 恒等于配对 Node 版本**（runtime/pty/cli 三件同版上线） | 与引擎同一棵源码树天然同版；镜像 pty 配对纪律 | 独立 semver（python-cli 因无 ABI 约束才独立，本仓不同） |
| **D5** | **npm/corepack JS 树走 assets→filesDir 幂等物化**（marker 纪律，同 python-cli stdlib / bridge payload） | 纯数据无需 exec 位；assets 不是文件系统路径，解释器/加载器需要真实路径 | JS 树放 jniLibs；直接从 APK 内路径读取 |
| **D6** | **npm/npx/corepack 壳脚本打入**：`libnpm.so` / `libnpx.so` / `libcorepack.so`（内容为 sh，jniLibs 随包落盘 nativeLibraryDir）→ `exec <nativeLibraryDir>/libnode_cli.so <物化树内 cli 入口> "$@"` | 首启即有 npm/npx/corepack 命令、离线可用、零引导步骤；壳脚本落在 nativeLibraryDir 合规 exec（内核只看 shebang，文件名无关）；npm 树取自 node 源码树 `deps/npm`（同源零下载）；corepack 树取自**单独钉版**官方 tarball（v2.2：Node 25 起树内已无 deps/corepack——sha256 钉 lock.builtFrom.corepackTar，镜像 python-cli pip wheel 纪律） | 只靠文档让用户手敲 `node …/npm-cli.js`；把命令入口放 filesDir（C1 不可 exec）；npm/corepack 不校验出处直接下载（违反 fetch 钉选纪律） |
| **D7** | **`--with-intl=full-icu` + `--with-icu-source=<钉版 icu4c 数据源>` + `llvm-strip --strip-unneeded` + `-Wl,-z,max-page-size=16384`** | **2026-11-05 修订**（修复设计 §4.1）：intl 从 `none` 改 **full-icu**——物理修复 `/\p{ID_Start}/u` 属性转义与 Intl 全 locale（`Intl.NumberFormat('zh-CN')`）；ICU 数据源**钉版本+sha256**（lock `builtFrom.sources.icu`，fetch-icu 步产出 `--with-icu-source`，configure 不再自行网下载）；16KB 页设备硬要求；体积预估 **100–106 MiB** ⬜ 首产实测回填 | `--with-intl=none`（Intl 不可用——原「有意分歧」口径作废）；`--with-intl=small-icu`（不足全 locale）；4KB 页对齐 |
| **D8** | **fetch 不改源；构建期补丁（若需）后置且逐条记录** | lock 出处纪律：源包 sha256 针对官方原包；补丁记录进 `builtFrom.patch`（与 runtime「patch 后置、幂等」同口径） | fetch 阶段打补丁；引入补丁却不记录出处 |

### 3.2 与 `aosp-node-runtime` 的同源关系（构建面的全部差异）

| 维度 | aosp-node-runtime（dlopen 引擎） | 本仓（exec CLI） |
|---|---|---|
| 源码树 | 同一棵官方 `node-v<ver>` 源码（fetch 不改源） | 同 |
| NDK 线 | **r30（30.0.16248370，clang 21.0.0）**：Node 26 / V8 14.6 需 clang≥19.1.0，r28 的 clang 19.0.1 编不过 `deps/v8/src/base/atomicops.h`（runtime workflow 实测） | **对齐 r30**（同一棵 26 树同一编译器要求）；首个 CI 实建钉版回写 lock ⬜ |
| configure | 补丁注入 `--shared`（+`--with-intl=small-icu`） | **不带 `--shared`**（D2）+ `--with-intl=full-icu --with-icu-source=<钉版 icu4c 数据源>`（D7 修订 2026-11-05）；上游 android_configure 固化继承 `--openssl-no-asm --cross-compiling` |
| 产物 | `out/Release/libnode.so`（ET_DYN、无 PT_INTERP） | `out/Release/node`（默认目标，⬜ M1 核实）→ 改名 `libnode_cli.so`（PIE + PT_INTERP=/system/bin/linker64） |
| 构建期补丁 | `patch-node-source.py` 四件（configure 参数 / trap-handler / cctest / cpu-features） | 子集复用评估 ⬜（§4.3） |
| ELF 门禁 | PT_INTERP=0 + 必须含 libnode.so + napi_* 门禁 | exec 型 profile（§6，三处相反/差异） |
| 打包 | `useLegacyPackaging=false`（APK 内 mmap 不落盘） | `true`（物理落盘，D1，相反） |
| C++ 运行时 | 随包 `libc++_shared.so` | 不随包；运行期经 `LD_LIBRARY_PATH=<nativeLibraryDir>` 由 runtime 供给 |

## 4. 构建设计（M1 核心）

### 4.1 工具链与源钉选

| 项 | 取值 | 说明 |
|---|---|---|
| Node 源 | `nodejs.org/dist/v<ver>/node-v<ver>.tar.xz`，SHASUMS256.txt 官方校验链 | fetch 不改源（D8）；现骨架脚本只固化接口，下载/解压/校验 M1 实现 |
| NDK | **r30（30.0.16248370）**，与 runtime 同线 ⬜ 首个 CI 实建钉版 | 一台 runner 一条 NDK 线；lock.builtFrom.ndk 记录 |
| host 工具链 | build-essential（gcc/g++ 作 CC_host/CXX_host 编 mksnapshot）、make、python3、xz | V8 host snapshot 工具在交叉编译中必需（runtime 同款前置） |
| 16KB 页 | `-Wl,-z,max-page-size=16384` 显式传入（NDK r28+ 默认已是 16384，双保险）⬜ 注入口 M1 拍板 | 门禁 ⑦ 硬判据 |
| npm | **取自同一棵源码树 `deps/npm`**（不单独下载，D6；✅ 实测 v26.13.0 树内 npm 11.20.0） | 版本 + 树 sha256 记 lock.builtFrom（§8） |
| corepack | **单独钉版官方 tarball**（registry.npmjs.org corepack-0.36.0.tgz，sha256 钉选；v2.2：树内无 deps/corepack） | `builtFrom.corepackTar` + 解包树摘要（§8） |

### 4.2 交叉编译流程（`build-node-cli-android.sh`，M1 实现）

```
① env：NDK r30 toolchain；TARGET=aarch64-linux-android24（API 24 = minSdk）
② fetch（M1-T1）：node-v<ver>.tar.xz + SHASUMS256.txt 校验 → .dist/src/node-src/（官方原样）；
   fetch-icu（✅ 2026-11-05 新增，修复设计 §4.1）：钉版 icu4c 数据源下载 + sha256 校验
   （lock builtFrom.sources.icu，版本 78.3）→ .dist/src/icu-src
③ patch 评估（M1-T2）：⬜ 按 §4.3 拍板是否复用 runtime patch 子集；引入则逐条记录
④ configure（✅ R2 已答，as-built）：android_configure.py 恰收 3 参不透传且无 exec 位 ⇒ 构建脚本
   等价复刻其 PATH/CC/CXX/GYP_DEFINES 后【直呼 ./configure】并追加 --with-intl=full-icu
   --with-icu-source=<icu-src>；CC_host/CXX_host 由 env 导出（免改源）；LDFLAGS 16KB 不经 env
   （configure 不读）——靠 NDK r28+ 默认 + 门禁⑦验证
⑤ make -j$(nproc) → out/Release/node（默认目标，无 --shared；✅ R3 已答：闭包含 embedtest 无挂链）
⑥ llvm-strip --strip-unneeded → 改名 libnode_cli.so（严禁 libnode.so，D3）——**先裁剪**
⑦ 校验：provision --inspect 于 **strip 后产物（= lock 钉定的发布形态）**全项硬判
   —— ET_DYN / PT_INTERP 恰 1 个且 = /system/bin/linker64 / DT_NEEDED 白名单 / SHA / size /
   LOAD align 全 16384。v2.3.1 顺序修正：strip 前校验的 sha/size 必与 lock 不一致
   （run 41676678760 实证，released 后显形）
⑧ npm/corepack 树收集（M1-T4）：deps/npm（同源）+ 钉版 corepack tarball 解包树 → 剪枝
   （✅ v2.2.1 定稿：剔除 test/tests/__tests__/docs/markdocs/man 目录 + node_modules/.bin + *.md；
   **保留 node_modules 本体**——npm-cli.js 的裸包名依赖全靠它解析，整删则 npm/npx 必然
   MODULE_NOT_FOUND；剔除计数登记 BUILD-METADATA）
   + manifest.json（逐文件 sha256 + 总 sha256）
⑨ 壳脚本生成（M1-T4）：libnpm.so / libnpx.so / libcorepack.so（模板生成，§6.1 三纪律）
⑩ BUILD-METADATA.txt / FETCH-METADATA.json（镜像 pty/runtime 归档形态）
```

要点与风险：

- **无 `--shared` 是本仓与 runtime 唯一的配置级分水岭**：runtime 经补丁把 `--shared` 注入
  configure；本仓恰要"什么都不加"地走默认路径，⬜ 首轮裸 configure 试编是 M1 第一风险项（R1）；
- **产物预估（full-icu）100–106 MiB**（strip 后；intl=none 首产实测 58.4 MiB 为历史口径，见 R4）⬜，
  首产实测回填 lock；体积缓解沿既有 Play 动态特性模块登记，不阻塞。
- 壳脚本引用的物化树内入口路径（`npm/bin/npm-cli.js`、npx-cli.js、corepack 入口）⬜
  以实际树为准在 M1-T4 拍板并写死进壳脚本模板。

### 4.3 runtime 构建期补丁的复用评估（⬜ M1-T2 首轮试编拍板）

runtime 的 `scripts/patch-node-source.py` 四件补丁均针对交叉编译本身（与 `--shared` 无关或
恰好相反），逐件评估：

| runtime 补丁 | 内容 | CLI（无 --shared）预期 | 判定 |
|---|---|---|---|
| configure 注入 `--shared` + small-icu | runtime 专用 | 恰好相反（本仓要无 --shared + full-icu，D7 修订） | **不复用** |
| `--v8-disable-temporal-support` | Node≥26 的 Rust Temporal crates 无 Android cross target，cargo 产 host x86_64 对象挂 aarch64 链接 | ✅ 已答（CI 首跑实测）：该标志是**真实选项**（configure.py:1277/2267 → v8_enable_temporal_support=0，node_crates 不进链接）——run 41449442265 于链接期复现 `libnode_crates.a incompatible with aarch64linux` 后确认；build 步③ 直呼 configure 显式传入（与 runtime 引擎同口径，§7 已知限制 5） |
| CC_host/CXX_host 导出 | gyp 需用 host 编译器编 mksnapshot 等快照工具 | ✅ 已答：构建脚本步① env 直接导出（等价 runtime 的 cc-host 补丁，免改源）；patcher 保留 cc-host id 仅供 wrapper 路径 |
| trap-handler.h 全局 `V8_TRAP_HANDLER_SUPPORTED=false` | host mksnapshot 与目标的编译一致性（host 对象引用未链接符号） | 与 shared/exec 无关，预期**仍需要** | ⬜（任务点名开放项） |
| node.gyp cctest 跳过 | 仅 `node_shared=="true"` 条件生效 | 预期**不需要**（非 shared 不触发该条件；cctest 非默认目标） | ⬜ 随 R3 一并核实 |
| cpu-features 编入 zlib 目标 | vendored zlib 调 `android_getCpuFeatures()`，common.gypi 只给头文件路径不给实现 | 预期**需要**（node 可执行同样链接 libzlib.a） | ⬜ |

纪律口径：fetch 产物保持官方原样（sha256 针对原包）；补丁（若拍板需要）发生在构建脚本内、
幂等、逐条记录进 `lock.builtFrom.patch`——与 runtime 现行做法完全同口径。

## 5. 制品形态与打包投放（AAR）

```
node-cli-<ver>.aar
├── jni/arm64-v8a/libnode_cli.so      # exec 型 PIE（ET_DYN + PT_INTERP=/system/bin/linker64，16KB 对齐）
├── jni/arm64-v8a/libnpm.so           # 壳脚本（sh）：exec libnode_cli.so <物化>/npm/bin/npm-cli.js "$@"（D6）
├── jni/arm64-v8a/libnpx.so           # 壳脚本（sh）：同上，npx-cli.js
├── jni/arm64-v8a/libcorepack.so      # 壳脚本（sh）：corepack 入口（⬜ 精确入口文件 M1-T4 以树为准）
└── assets/node-bridge-tools/
    ├── npm/…                         # deps/npm 纯 JS 树（剪枝后）
    ├── corepack/…                    # corepack 纯 JS 树（✅ v2.2：单独钉版 tarball 解包，非 deps/corepack）
    └── manifest.json                 # 文件清单 + 逐文件 sha256 + 总 sha256
```

- 打包：**`useLegacyPackaging=true`**（D1）；模块只作 AAR 容器，无任何 Kotlin/Java 源；
- 产物**只有一个 ELF**（libnode_cli.so）；`libc++_shared.so` 由 node-runtime 统一供给
  （绝不随包，防同名冲突）；exec 时须 `LD_LIBRARY_PATH=<nativeLibraryDir>`；
- provision 扩展（M1-T5）：`--assets <dir>` 投放 assets 并生成/校验 manifest.json；
  `--shims <dir>` 校验+投放壳脚本（模板由 build 脚本生成，生成器与校验器分离）；
- 命令可达性：`npm` 等命令名 ≠ 文件名 `libnpm.so`，PATH 直查不中——消费方经
  `$HOME/bin` symlink 农场（`npm → <nativeLibraryDir>/libnpm.so`）或 `pty.spawn` 绝对路径
  直启；`node` 命令名同理经 `node → libnode_cli.so` symlink；
- META-INF/node-cli.properties 增补（M1）：`npm.version` / `corepack.version`（读已投放树内
  package.json）/ `assets.sha256`（manifest 总摘要）；`ndk`/`flags` 随 lock 回写进 builtFrom；

## 6. exec 型门禁 profile

| 门禁 | 判据 | 与 pty（dlopen 库）门禁的差异 |
|---|---|---|
| ELF 形态 | `ET_DYN`（PIE） | 同 |
| 解释器 | **PT_INTERP 恰 1 个且 = `/system/bin/linker64`** | **相反**（pty 要求 PT_INTERP=0） |
| 依赖 | **DT_NEEDED 白名单**（系统库 + lock matrix.allowedNeeded 登记；`libc++_shared.so` 在白名单但不随包） | pty 是"必须含 libnode.so" |
| NAPI | 无门禁（CLI 是独立进程，不解析 napi_*） | pty 有"napi_* 未定义引用"门禁 |
| 页对齐 | 16KB（`-Wl,-z,max-page-size=16384`） | 同 |
| 出处 | sha256 / size / 源版本 / NDK / flags / 补丁 | 同 |

- **已实现（M0）**：provision 退出码 0/2/1；门禁 ①–⑦；draft 只记录不比对；
  BANNED_IN_AAR（libnode.so / libc++_shared.so）恒拒；
- **M1 新增**：① `--assets` 投放 + manifest 生成/校验；② **assets 静态性检查**——assets 树内
  不得出现 ELF magic 文件（npm/corepack 树纯 JS/JSON/文档，防任何二进制漏网；.wasm 属数据
  ⬜ M1 评估放行与否）；③ **壳脚本校验**（§6.1）；④ `--shims` 投放流程。

### 6.1 jniLibs 兄弟文件白名单扩展设计（M1-T5 实现项）

现状差距：provision `--check` 的兄弟文件规则（tools/provision.mjs 第 222–225 行）只放行
**单一** `libnode_cli.so`，任何兄弟 `.so` 判非法——投放壳脚本前必须先扩展。设计：

| 分类 | 判据 | 处置 |
|---|---|---|
| ELF | 文件头 magic = `0x7f 'E' 'L' 'F'` | 走 §6 exec 门禁全套；文件名必须 = `libnode_cli.so` |
| 壳脚本 | 文本、首行 `#!` | 名称 ∈ lock `matrix.shellShims` 白名单 + 下表壳校验；sha256/size 入 lock（draft 仅记录） |
| 其余 `.so` | — | 拒绝（BANNED_IN_AAR：`libnode.so` / `libc++_shared.so` 恒拒，白名单不豁免） |

壳脚本校验判据（全部满足才放行）：

1. 名称 ∈ 白名单（`libnpm.so` / `libnpx.so` / `libcorepack.so`，lock `matrix.shellShims` 登记）；
2. shebang = `#!/system/bin/sh`（内核按 shebang 解释执行，与扩展名无关）；
3. exec 目标仅限：`$NODE_NATIVE_DIR/libnode_cli.so` + 物化树内 `.js` 入口；内容不得出现
   `libnode.so` / `libc++_shared.so` / 任何其他 ELF 引用；
4. 禁止网络/下载类命令（curl/wget/…⬜ 关键词黑名单 M1 定稿——C2 纪律在脚本层同样生效）；
5. sha256 + size 记入 lock（draft 仅记录；released 后严格比对）。

白名单事实源在 lock `matrix.shellShims`（§8），provision 只读 lock 不自带清单——防止工具与
事实源漂移。

## 7. 运行期契约（消费方 / 环境引导层）

| 环境变量 | 值 | 说明 |
|---|---|---|
| `HOME` | `<filesDir>/home` | npm 缓存 / global prefix 根 |
| `TMPDIR` | `<filesDir>/tmp` | npm 临时目录 |
| `PATH` | `<nativeLibraryDir>:$HOME/bin:/system/bin` | `node` 经 $HOME/bin symlink 以命令名直出（命令名≠文件名） |
| `LD_LIBRARY_PATH` | `<nativeLibraryDir>` | ⚠️ **v2.3.1 契约修订（2026-11-03 设备探针实证）**：Android 16+ 对 app 孵化的 exec 型进程**不再采纳 LD_LIBRARY_PATH**（export/prefix 两形态均失效）——libc++_shared 的「runtime 供给 + env 注入」契约不可达 ⇒ 产物改**静态链接 libc++**（`-static-libstdc++`，DT_NEEDED 只剩系统库），本变量不再承担链接职责（保留为 PATH 兼容项） |
| `NODE_TOOLS_DIR` | `<filesDir>/node-bridge-tools` | 物化后 npm/corepack 树根（壳脚本引用） |
| `NODE_NATIVE_DIR` | `<nativeLibraryDir>` | 壳脚本兜底定位 `libnode_cli.so`（注：`dirname "$0"` 兜底仅覆盖 nativeLibraryDir 直启——经 `$HOME/bin` symlink 调用时兜底解析到 `$HOME/bin/libnode_cli.so` 不存在，故消费方**必须**注入本变量或以绝对路径直启） |
| `npm_config_prefix` | `$HOME` | `npm i -g` 落 `$HOME/lib/node_modules`（默认 `/usr/local` 不可写） |
| `npm_config_cache` | `$HOME/.npm` | |
| `npm_config_update_notifier` | `false` ⬜ | 免首启联网检查（待评估） |
| `COREPACK_ENABLE_DOWNLOAD_PROMPT` | `0` ⬜ | 防交互阻塞；下载边界见 R6 |

- 物化机制：`assets/node-bridge-tools/` → `<filesDir>/node-bridge-tools/`，复用 bridge payload
  纪律（marker 幂等、失败结构化上报、版本升级时清残留）；
- TLS/CA：Node 内嵌 Mozilla CA store（与 python-cli 需随包 cacert.pem 不同），⬜ 由探针 P10 真机核验；
- **已知限制（消费方文档必须写明，能力边界非缺陷）**：
  1. `npm i -g` 装出的 bin 脚本落在 filesDir：C1 不可直接 exec，且 `#!/usr/bin/env node`
     在 Android 上无 `/usr/bin/env` 可寻 → 只能经 `npx`、或 `node <脚本路径>` 显式调用；
     安装期 shebang 改写器（Termux 做法）列为 **M2 可选项** ⬜；
  2. 设备无编译器：npm 装带 node-gyp 原生构建的包必失败 → 错误如实上报（探针 P7），
     绝不静默降级；
  3. corepack 运行期下载 pnpm/yarn 与 C2 冲突：pnpm 12+ 为 Rust 可执行件 ⇒ **禁止经 corepack
     获取可执行件**；pnpm 走独立 `aosp-pnpm-cli` 线（工作区方案 §9.3）；corepack 仅用于
     `--version` 与钉版 JS 兜底；
  4. Intl API **full-icu 全量可用**（D7 修订 2026-11-05：CLI 从 intl=none 改 full-icu 内嵌数据，
     `/\p{ID_Start}/u` 属性转义与全部 Intl locale 可用，无 `NODE_ICU_DATA` 依赖；与 runtime 的
     small-icu 交付面不同——CLI 全量、runtime 默认 locale 子集）；
  5. Temporal API 不可用（若 §4.3 拍板 `--v8-disable-temporal-support`；与已发布 runtime 引擎同口径）。
  6. **v2.3.1**：app 孵化 exec 的 `LD_LIBRARY_PATH` 不被 linker 采纳（Android 16+ 加固，
     2026-11-03 API 37 模拟器 run-as 对照实证）——静态 libc++ 后不影响本仓产物；
     **对配对 runtime 引擎（dlopen libnode.so 的消费方）不适用**（dlopen 走 Java 装载器命名空间，另一机制）。

## 9. CI 设计（真实流水线，M1-T6 替换 scaffold CI）

- **双 job 布局**：`config-check`（保留现 scaffold CI：Gradle 配置期门禁 + provision 自检 +
  脚本语法门，push/PR 触发）+ `build-android-arm64-v8a`（真实流水线，下述）；
- 触发：push tag `v<nodever>`（如 `v26.13.0`）或 workflow_dispatch（inputs：node_version /
  android_api，镜像 runtime）；permissions `contents: write`（Release）；
- runner：`ubuntu-24.04`；**不设 timeout-minutes**（冷 V8 交叉编译可数小时，6h 平台上限；
  runtime 同款经验）；装机：build-essential、curl、file、make、python3、unzip、xz-utils、
  JDK 21 + Gradle 9.4.1（仅 config-check job 需要）、**NDK r30**；
- **16GB swapfile**：V8 host snapshot 编译峰值可超 runner 16GB RAM（runtime 实测教训）；
- 步骤链：checkout → 装机 + swap → 装 NDK r30 → **fetch**（tar.xz + SHASUMS256.txt 校验，
  不改源）→ ⬜ patch 子集（§4.3 拍板后）→ **fetch-icu**（钉版 icu4c + sha256，lock `builtFrom.sources.icu`）→ **configure**（无 `--shared` + `--with-intl=full-icu --with-icu-source=<icu-src>` +
  LDFLAGS 16KB；注入方式 ✅ R2 直呼 ./configure）→ **make -j** → 校验 `out/Release/node`（file/readelf：PIE +
  PT_INTERP + 16KB LOAD align，镜像 runtime 校验段）→ **strip**（llvm-strip --strip-unneeded）
  → 改名 `libnode_cli.so` → **npm/corepack 树收集**（剪枝 + manifest 逐文件 sha256）→
  壳脚本生成 → **provision 全门禁**（ELF + shims + assets 静态性）→ 归档
  `node-cli-v<ver>-android-arm64-v8a.tar.gz`（libnode_cli.so + 三壳脚本 + npm/corepack 树 +
  manifest + BUILD/FETCH-METADATA + LICENSES）+ `.sha256` → **GitHub Release**（tag 钉 commit）
  → artifact 上传；lock 人工回写（M4 评估自动化）；
- 缓存：v2.2.1 定稿——`actions/cache` 只缓存 `.dist/src/downloads`（源包原件，键含 lock 哈希；
  fetch 可重入保证命中正确性）；**不缓存**解压树/编译树（configure/patch 副作用与增量脏树会破坏
  「干净 runner 同口径产物」）；ccache / NDK 安装缓存 ⬜ 首轮实测耗时后定。
